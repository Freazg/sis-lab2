# PRD — Motion-Mirroring Teleoperator

**Курс:** Системне програмування вбудованих систем · **Тема:** №6 з каталогу (Додаток A)
**Платформа:** NUCLEO-C031C6 у Wokwi (ЛР1) → перенесення на NUCLEO-F411RE/F446RE на залізі
**Версія:** 0.1 (ЛР1)

## A. Загальна ідея

Пристрій «дзеркалить» рух кисті оператора на двовісний маніпулятор. IMU MPU-6050 закріплено на кисті (липучка). Мікроконтролер 200 разів на секунду обчислює орієнтацію кисті (pitch / roll) через sensor fusion, фільтрує тремтіння і перетворює кути на положення двох сервоприводів pan-tilt. Затримка «рух руки → рух серво» має бути меншою за 50 мс від кінця до кінця.

Друга функція — запис траєкторії. Оператор вмикає режим REC, рухи пишуться у SPI-флеш W25Q64. Потім маніпулятор відтворює їх без оператора (PLAYBACK). Так навчають промислових роботів «показом» (teach-by-demonstration). Цільові користувачі: навчальні лабораторії робототехніки, прототипи телеманіпуляторів для небезпечних середовищ, реабілітаційні стенди, де потрібен контрольований повтор рухів. Повноцінні аналоги (хірургічні системи Intuitive Surgical, маніпулятори для АЕС) коштують на порядки більше, а принцип той самий: IMU → fusion → сервоконтур з обмеженою латентністю.

## B. Функціональні вимоги

| ID | Вимога |
|---|---|
| FR-01 | Система повинна зчитувати акселерометр і гіроскоп MPU-6050 по I²C з частотою **200 Hz** (період 5 мс ± 0.5 мс). |
| FR-02 | Система повинна обчислювати pitch і roll комплементарним фільтром. Похибка в статиці ≤ **2°** відносно еталонного нахилу. |
| FR-03 | Система повинна відпрацьовувати рух кисті на серво з латентністю ≤ **50 мс** від зміни на IMU до оновлення PWM. |
| FR-04 | Система повинна формувати PWM 50 Hz для двох серво з роздільністю ≤ **1°** і програмними межами ходу (за замовчуванням 10–170°). |
| FR-05 | Система повинна пригнічувати тремтіння: dead-zone ±**1.5°** і обмеження швидкості серво ≤ **300°/с**. |
| FR-06 | Користувач повинен перемикати режими LIVE → HOLD → REC → PLAYBACK кнопкою B1 (коротке натискання). Поточний режим видно за LED і в UART-лозі. |
| FR-07 | У режимі REC система повинна записувати траєкторію у W25Q64 з частотою 50 Hz, тривалістю не менше **60 с** на запис. |
| FR-08 | Записана траєкторія повинна зберігатися після вимкнення живлення і відтворюватися з тим самим таймінгом (похибка ≤ 20 мс на 60 с). |
| FR-09 | Потенціометр повинен задавати «нуль» (калібрування зміщення pan) або, у режимі HOLD, вручну керувати pan. |
| FR-10 | Система повинна надавати CLI по UART 115200: `status`, `cal`, `mode <live|hold|rec|play>`, `limits <min> <max>`, `dump`. |
| FR-11 | При втраті зв'язку з IMU (немає ACK > 100 мс) система повинна зафіксувати серво в останньому безпечному положенні і повідомити про помилку в UART. |
| FR-12 | Система повинна вимірювати власну латентність: GPIO-маркер на подію «IMU прочитано» і «PWM оновлено» для логічного аналізатора. |

## C. Датчики та виконавчі пристрої

| Компонент | Інтерфейс | Навіщо (які FR) | Альтернативи і чому відкинуті |
|---|---|---|---|
| **MPU-6050** (GY-521), InvenSense | I²C @ 0x68 | Джерело орієнтації кисті: FR-01, FR-02, FR-03, FR-11 | **GY-89** (L3GD20 + LSM303D + BMP180): дає магнітометр для абсолютного yaw, але це 3 чипи на шині і складніший fusion. Лишаємо як розширення. **BNO055**: має апаратний fusion, але приховує алгоритм, а мета курсу — написати fusion самому. До того ж дорожчий. **ADXL345** (лише акселерометр): без гіроскопа не відфільтрувати динамічні прискорення. |
| **W25Q64JV**, Winbond | SPI mode 0 | Збереження траєкторій і конфігурації: FR-07, FR-08 | **Внутрішня flash MCU**: на C031 32 KB, на F411 512 KB, але стирання сторінками блокує CPU і зношує пам'ять прошивки. **microSD**: потрібна FAT-файлова система, великі затримки запису, зайве для ~200 KB даних. **AT24C256 EEPROM** (I²C): 32 KB — менше ніж 60 с запису, і ділить шину з IMU. |
| **Потенціометр** 10 kΩ (на залізі — або GM5528) | ADC1_IN0 | Калібрування нуля і ручне керування: FR-09 | **Енкодер KY-040**: точніший, але потребує EXTI/таймер-енкодер і не дає абсолютного положення після ресету. |
| **Кнопка B1** (на платі) | GPIO / EXTI | Перемикання режимів: FR-06 | Окрема клавіатура — зайве для 4 режимів. |
| **2× SG92R** серво | PWM (TIM3 CH1/CH2) | Виконавчий механізм pan-tilt: FR-03, FR-04, FR-05 | **MG90S** (металеві шестерні): міцніші, але важчі і з більшим струмом. **Крокові 28BYJ-48**: повільні (~15 об/хв), не вкладаються в 50 мс. |
| **UART** (ST-Link VCP / FT232RL) | USART2 115200 8N1 | Логи, CLI, вивантаження траєкторій: FR-06, FR-10, FR-11 | — |

Мінімальна вимога курсу (≥ 3 сенсори з різними інтерфейсами): **I²C** (MPU-6050) + **ADC** (потенціометр) + **GPIO** (кнопка) + **SPI** (W25Q64, на залізі). Виконавчі пристрої — **PWM**.

## D. План тестування

| FR | Тест | Критерій проходження |
|---|---|---|
| FR-01 | Toggle GPIO на кожне читання IMU. Логічним аналізатором (Saleae / Wokwi Logic Analyzer, VCD → PulseView) виміряти період за 10 с. | Середній період 5.0 мс, джиттер ≤ 0.5 мс |
| FR-02 | Покласти IMU на рівну поверхню, потім на клини 15°, 30°, 45° (у Wokwi — задати `accelX/Z` повзунками). Порівняти pitch у лозі з еталоном. | |Δ| ≤ 2° для всіх кутів |
| FR-03 | GPIO-маркер A при різкій зміні кута IMU, маркер B при записі нового CCR. Виміряти B − A на 20 подіях. | max ≤ 50 мс, середнє ≤ 25 мс |
| FR-04 | Логічним аналізатором виміряти ширину імпульсу на 0°, 90°, 180° і на межах `limits`. | 50 Hz ± 1 %; ширина відповідає формулі ± 10 мкс; серво не виходить за межі |
| FR-05 | Подати на IMU синусоїдальне «тремтіння» ±1° (у Wokwi — повзунок) і різкий стрибок 90°. | При ±1° серво нерухомі; стрибок 90° відпрацьовується не швидше ніж за 300 мс |
| FR-06 | Натиснути B1 4 рази, перевірити лог і LED на кожному кроці. Перевірити брязкіт: 20 швидких натискань. | Послідовність LIVE→HOLD→REC→PLAY→LIVE, жодного пропуску чи подвійного спрацювання |
| FR-07 | Записати 60 с руху. Командою `dump` вивантажити кількість семплів. | ≥ 3000 записів (50 Hz × 60 с), CRC блоку збігається |
| FR-08 | Записати траєкторію, вимкнути живлення, увімкнути, `mode play`. Логічним аналізатором порівняти PWM запису і відтворення. | Записи читаються після ресету; розбіжність таймінгу ≤ 20 мс на 60 с |
| FR-09 | Повернути потенціометр у 0 %, 50 %, 100 % у режимі HOLD. | pan = 0°/90°/180° ± 2° (з урахуванням `limits`) |
| FR-10 | Виконати кожну CLI-команду, а також невідому команду і рядок > 64 символів. | Коректні відповіді; на помилковий ввід — `ERR`, без зависання |
| FR-11 | Під час роботи від'єднати SDA (у Wokwi — видалити дріт / зупинити IMU). | Через ≤ 100 мс у лозі `IMU lost`, серво стоять, після повернення — автоматичне відновлення |
| FR-12 | Перевірити наявність маркерів на каналах аналізатора і зберегти VCD у `docs/screenshots/`. | Обидва маркери видно, FR-03 вимірюється з них |

## E. Поетапний план (ЛР1 → ЛР4)

| ЛР | Результат |
|---|---|
| ЛР1 | Тулчейн, bring-up усіх інтерфейсів, WHO_AM_I, сирі дані, пряме відображення pot → pan і pitch → tilt (прототип FR-03/04) |
| ЛР2 | Драйвер MPU-6050 з калібруванням, комплементарний фільтр, таймер 200 Hz (FR-01, FR-02, FR-05) |
| ЛР3 | Драйвер W25Q64, формат запису траєкторії (Δ-encoding + keyframes), REC/PLAY (FR-07, FR-08) |
| ЛР4 | CLI, обробка помилок, вимір латентності, фінальне тестування за таблицею D |
